# 登录账号与权限管理

入口为 `/permissions`，只向通过管理验证的超级管理员开放。账号可设置一个角色、多个主体；未分配主体的普通账号没有业务数据范围。禁用、重置密码、修改账号/角色授权和强制退出均撤销相应旧会话。

## 兼容与部署

- 先备份，确认至少有一个启用的旧 `admin`；该角色原值保留，对应超级管理员。新增数据库账号的默认角色改为 `viewer`，不运行 seed。
- 首次部署前执行一次 `prisma/add-permissions.sql`，再生成 Prisma 客户端，构建后端和前端，检查后台任务后发布。不要在生产使用全量 db push。
- 生产使用非默认的登录密码、独立的 JWT 签名密钥和 HTTPS。超级管理员继续使用原管理专用凭证进入受保护页面，普通账号验证本人密码。二次验证不会授予额外操作权。
- 新账号默认不具有跨主体、删除、客户导出或查看备注手机号权限。角色设置中的写入、同步及导出操作依赖对应模块的查看权限。管理员不通过应用读取他人工作台内容。
- 运营人员默认具有“用户迁移查看与处理”，仅能查看、刷新、编辑备注和推送已分配主体的记录。已自定义的角色策略保留，由管理员在权限管理中勾选该项。采集配置、导出、删除以及交接模块仍仅对管理员开放。
- 首次启用迁移授权时，管理员在“用户迁移 → 采集信息 → 运营主体映射”核对源表选项并保存。仅唯一同名项会被预选，别名需手动匹配。未绑定主体的记录不会展示，未分配主体的账号不会获得任何记录。服务器需持久化迁移快照目录（含 operator-access.json）。
- 权限变更与审计写入同一数据库事务。安全事件只保存账号编号、操作、目标和时间，不记录凭证或客户明文。默认保留30天，启动及每日清理；可通过 SECURITY_AUDIT_RETENTION_DAYS 配置1至365天。页面展示最近200条，不改变数据库二进制日志策略。

## 验证

后端的 `tests/permissions.integration.mjs` 只接受回环数据库地址；需要有创建临时测试库权限的独立 MySQL 实例。测试完成后仅删除其随机命名的测试库。前端 `tests/permissions.browser.mjs` 使用模拟业务数据验证桌面、手机、管理员及只读页面。
